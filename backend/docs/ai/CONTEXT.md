# Контекст backend «Нортландии онлайн»

Дата сверки: 2026-09-14. Этот файл самодостаточен для IDE, открытой только на `backend/`.

## Текущее состояние

- Есть стандартный каркас Django: `manage.py`, пакет конфигурации `backend/`, admin endpoint и папка `templates/`.
- `settings.py` читает `backend/.env` через `django-environ`. Версионируемый шаблон — `backend/.env.example`; локальный `.env` исключён из Git. PostgreSQL 16 запускается сервисом `postgres` из корневого `compose.yaml`; контейнер и Django используют общие переменные `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST` и `POSTGRES_PORT` без единой строки подключения.
- Утверждённая версия проекта — Django 6.1.1 на Python 3.13. Перед установкой зависимостей проверить interpreter PyCharm; зависимости зафиксированы в `requirements.txt`.
- Системный Python при сверке — 3.13.9; Django в системном интерпретаторе не установлен. PyCharm может использовать другое окружение — проверять выбранный interpreter.
- `requirements.txt` фиксирует Django и зависимости утверждённого runtime-стека: DRF, Psycopg, `django-environ`, `drf-spectacular`, Celery/Redis и `django-storages`/S3. Прикладные DRF endpoints, OpenAPI, фоновые задачи и S3 storage ещё не подключены; тестовая инфраструктура отсутствует.
- Git-репозиторий находится уровнем выше, в `nortland-online/`.

## Целевой стек

Python 3.13, Django 6.1.1, Django REST Framework, PostgreSQL через Psycopg 3, `django-environ`, `drf-spectacular`, Celery + Redis, `django-storages` + S3/MinIO. Проверки: pytest, pytest-django, factory-boy, coverage, Ruff, mypy + django-stubs. Gunicorn и reverse proxy относятся к развёртыванию, а не к локальному `runserver`.

## Критические правила

- Первый этап: публичная заявка → организатор подтверждает оплату → создаёт взрослый и детский кабинеты. Родитель не создаёт ребёнка сам.
- Родитель видит только связанных детей. Чат закрыт по умолчанию и открывается отдельным разрешением для пары родитель–ребёнок.
- Браузер создаёт задания в линиях своего персонажа. Публикация требует готовности браузера, методиста и гейм-мастера плюс обязательные материалы; архивирует организатор.
- Просмотр задания не создаёт `child_task`; экземпляр появляется только после действия «Взять».
- Доработка создаёт новую попытку, старая попытка и её файлы сохраняются.
- `accruals` — источник истины экономики. Токены относятся к мастерской, репутация — к паре ребёнок–персонаж; кэши производны.
- Первое знакомство фиксируется для пары ребёнок–персонаж один раз. Выбор первой/повторной реплики нельзя определять после записи даты в том же запросе.

## API-соглашения

- Базовый префикс: `/api/`; окончательные endpoints появляются только вместе с OpenAPI-схемой.
- UUID передаются строками, даты-время — ISO 8601 с timezone, детский код — строка из шести цифр.
- В ответах использовать отдельные read/write serializers. Не отдавать хеши, служебные поля и чужие закрытые данные.
- Списки имеют пагинацию, сортировку и явные фильтры. Ошибки содержат стабильный машинный `code`, сообщение и ошибки полей.
- Cookie-сессии требуют HttpOnly, Secure в production, SameSite и CSRF. Сессия явно различает взрослого и ребёнка.
- Опасные повторные действия имеют ключ/ограничение идемпотентности; блокировка кнопки на фронте не является защитой.
