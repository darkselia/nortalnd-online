# Контекст frontend «Нортландии онлайн»

Этот файл самодостаточен для IDE, открытой только на `frontend/`. Личные сведения об окружении находятся в необязательном `docs/local/ENVIRONMENT.md`, исключённом из Git.

## Текущее состояние

### Границы MVP — решение от 2026-09-29

Обязательны вход и кабинеты родителя и ребёнка, каталог мастерских, диалоги, выполнение заданий с файлами и чатом, числовые награды и прогресс. Сотрудник создаёт ветки и задания, согласует их и проверяет работы в отдельном кабинете сайта; три согласования сохраняются.

Приём семьи и оформление идут вне сайта. Нужен закрытый интерфейс создания разрешённых аккаунтов и семейных связей, но публичная регистрация, формы заявок и их обработка отложены. Также после MVP идут организации, сертификаты, автоматизация оплаты и карта. Django admin служит начальной настройке сотрудников и поддержке; рабочие экраны контента и проверки создаются на Nuxt. Разрабатывать каждый модуль вместе с его API и проверками по корневому ROADMAP.md; нерешённые формулы и права не додумывать.

### Реализованная основа

- Создано Nuxt-приложение: Nuxt 4.5.2, Nuxt UI 4.11, Pinia, Tailwind CSS 4 и TypeScript.
- Требование проекта — Node.js 24 LTS. Поле `packageManager` в `package.json` не задано. Диапазоны зависимостей указаны в manifest, точные версии установки — в `package-lock.json`.
- Реальные scripts: `dev`, `build`, `preview`, `postinstall`, `lint`, `typecheck`, `test` (`vitest run --passWithNoTests`) и `test:watch` (`vitest --passWithNoTests`).
- Русскоязычная стартовая страница использует отдельные `AppHeader` и `AppFooter`. Светлая и тёмная темы задаются общими токенами в `app/assets/css/theme.css`; семантические роли и оформление Nuxt UI — в `app/app.config.ts`. В шапке есть `UColorModeButton`, исходная тема светлая. `main.css` содержит только импорты и глобальную основу, локальные стили находятся в компонентах/странице. Изображения скопированы в `app/assets/images/`, прямых импортов из прототипа нет. Кнопки входа пока неактивны; контакты — заготовки без реквизитов.
- `app/error.vue` отображает неизвестные адреса с кодом 404 и русским текстом, остальные ошибки — с нейтральным сообщением без технических подробностей. Экран использует существующие шапку/футер и тему; кнопка «На главную» очищает ошибку через `clearError({ redirect: '/' })`. Индикаторы загрузки пока не добавлены.
- Vitest содержит две проверки API в `tests/unit/api.spec.ts`: CSRF и передачу запросов через прокси. Для будущих компонентных тестов сохранено Nuxt-окружение с Vue Test Utils и Happy DOM; постоянных компонентных тестов пока нет. Команды и правила очистки: [TESTING.md](../TESTING.md). Playwright и generated OpenAPI types пока не добавлены. Прикладных Django API endpoints пока нет.
- Загрузка внешних шрифтов Nuxt UI отключена только в тестовом окружении.
- Nuxt-плагин предоставляет `useNuxtApp().$api` с `request/get/post/put/patch/delete`. `app/utils/apiClient.ts` использует встроенный `$fetch`, сохраняет данные Django и возвращает результат `ok` без обязательного try/catch в компонентах.
- Запросы идут на `/api/v1/` через H3-прокси `/api/...`. Закрытый `runtimeConfig.backendOrigin` задаётся переменной `NUXT_BACKEND_ORIGIN`; пример находится в `.env.example`, реальные значения — в игнорируемом `.env`. Сохраняются cookies, Set-Cookie, исходные Host/Origin/Referer; кэш и переадресации отключены. Плагин использует `useRequestFetch()` на SSR и создаётся для конкретного Nuxt-приложения.
- Для загрузок использовать `useAsyncData` с результатом `ok` и `refresh()`. Изменяющие запросы выполнять в браузерных обработчиках: перед каждым вызовом читается актуальный csrftoken; без него возвращается `csrf_missing` без отправки. Собственного timeout у клиента и прокси нет; отмена выполняется через AbortSignal. Автоматические повторы, общий экран ошибок и уведомления не добавлены. Клиент проверяет основную оболочку ответа и доверяет Django для содержимого pagination и ошибок полей. Инструкции и примеры: [API.md](../API.md).
- В 3.12 остаются подключение реальных endpoints после взрослого входа Django (3.7), получение первого CSRF и генерация DTO из OpenAPI, совместно с формой 3.14. Детский вход и семейные операции подключаются по мере готовности backend. При интеграции проверить настоящий Django API, включая вход/выход, перезагрузку и изоляцию пользователей при SSR; транспортные тесты не являются проверкой входа.
- Git-репозиторий находится уровнем выше, в `nortland-online/`.

## Целевой стек и структура

Nuxt 4, Vue 3, TypeScript strict, Tailwind CSS, Pinia и Nuxt UI. Тесты: Vitest + Nuxt Test Utils для unit/component и Playwright для E2E. Предпочтительная структура по мере появления кода:

```text
app/
  components/    общие и доменные UI-компоненты
  composables/   сценарии, загрузка и мутации
  pages/         маршруты и композиция страниц
  stores/        только разделяемое клиентское состояние
  types/         ручные UI-типы; generated API-типы отдельно
  assets/        дизайн-токены и стили
```

Не создавать пустые архитектурные слои заранее; добавлять их вместе с первым реальным сценарием.

## Критические правила отображения

- Взрослый и ребёнок входят через разные формы и получают разные типы сессии.
- Настоящее ФИО ребёнка закрыто; в игровой части используется `display_name`.
- Родитель видит только связанных детей, а переписку — только при отдельном разрешении для конкретной пары.
- Карточка мастерской и персонаж линии — не одно и то же. Сцена использует фон линии и фигуру текущего узла.
- Предпросмотр задания не означает «Взять». История попыток сохраняется, несколько файлов показываются отдельно.
- Награды, репутация и публикация отображаются только после подтверждённого ответа сервера.
- Для кабинета команды нужны раздельные состояния готовности браузера, методиста и гейм-мастера; архивирует организатор.

## API-соглашения

- API принадлежит Django и доступен под `/api/`; endpoint считается существующим только после появления OpenAPI-схемы.
- UUID — строки, timestamp — ISO 8601 с timezone, детский код — строка из шести цифр.
- API errors должны иметь стабильный машинный `code`, понятное сообщение и ошибки полей.
- Списки должны поддерживать пагинацию; не загружать всю историю сообщений/попыток одним запросом.
- Cookie-сессии требуют передачи credentials и CSRF для изменяющих запросов. Не помещать токены или детские коды в localStorage.
- Двойной клик блокировать в UI, но повтор запроса обрабатывать по контракту: идемпотентность обеспечивает backend.

## Открытые вопросы

Не придумывать UX, который закрепляет нерешённое правило: восстановление взрослого доступа и подтверждение контактов (Q02), редактирование после согласований (Q04), текстовый ответ диалога (Q06), награды (Q07), отказ/репутация (Q08), сертификаты (Q09), формула прогресса (Q10), родительский чат и аудит (Q11), лимиты/модерация (Q13), подписки (Q14), дополнительный контент (Q17), транслитерация и совпадения детского логина (Q18).

## Визуальное направление

Интерфейс русскоязычный и mobile-first. Игровая часть строится вокруг иллюстрированных мастерских, персонажей, диалоговых сцен, карточек заданий, карты и бейджа ребёнка. Служебные кабинеты организатора, методиста, браузера и гейм-мастера должны быть спокойнее и функциональнее: формы, таблицы, фильтры, статусы и модальные подтверждения на Nuxt UI. Цвета, типографику, отступы и скругления оформлять как токены проекта; не оставлять оформление starter-шаблона.

## Настройка темы

- Исходные палитры, радиусы и тени объявлены через `@theme` в `app/assets/css/theme.css`. Цветовые литералы находятся только в определениях токенов; компоненты используют переменные и семантические классы.
- `app.config.ts` назначает палитры ролям Nuxt UI (`primary: nortland`, `neutral: slate`) и общие настройки компонентов. Значения `--ui-primary`, `--ui-bg`, `--ui-text`, границ и дополнительных проектных ролей переопределяются в `:root` и `.dark` файла темы. Для замены оформления изменять токены и их семантические привязки там.
- Классы Nuxt UI (`bg-default`, `bg-muted`, `text-default`, `text-muted`, `border-default`) и проектные (`bg-page`, `shadow-card`) автоматически реагируют на режим. Отдельные цветовые `dark:` не требуются. `UColorModeButton` использует Nuxt Color Mode и сохраняет выбор; исходное предпочтение — светлое.
- При изменении оформления проверять обе темы, мобильную и широкую компоновку, переключение/перезагрузку, изображения и используемые компоненты Nuxt UI.
