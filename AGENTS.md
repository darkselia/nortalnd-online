# Нортландия онлайн — общие инструкции для ИИ

Инструкции действуют для всего монорепозитория. Общение и пояснения — на русском; имена кода, таблиц и API — на английском по соглашениям выбранного стека.

## С чего начать

1. Прочитать [навигацию](docs/ai/README.md), [стек](docs/ai/STACK.md) и [предметную область](docs/ai/DOMAIN.md).
2. Для backend-задачи прочитать [backend/AGENTS.md](backend/AGENTS.md), [backend-контекст](backend/docs/ai/CONTEXT.md) и [BACKEND.md](docs/ai/BACKEND.md).
3. Для frontend-задачи прочитать [frontend/AGENTS.md](frontend/AGENTS.md), [frontend-контекст](frontend/docs/ai/CONTEXT.md) и [FRONTEND.md](docs/ai/FRONTEND.md).
4. Для интеграции прочитать [API.md](docs/ai/API.md), найти модуль в [MODULES.md](docs/ai/MODULES.md) и проверить [OPEN_QUESTIONS.md](docs/ai/OPEN_QUESTIONS.md).

Не загружать все документы для локальной правки: достаточно затронутого модуля, его зависимостей и контракта.

## Источники и приоритет

1. Текущий запрос пользователя.
2. [DOMAIN.md](docs/ai/DOMAIN.md) — утверждённые бизнес-правила.
3. [OPEN_QUESTIONS.md](docs/ai/OPEN_QUESTIONS.md) — нерешённые места, которые нельзя додумывать.
4. [schema.json](docs/ai/schema.json) — логическая модель хранения, но не готовые Django models и не публичные DTO.
5. `backend/` и `frontend/` — фактически реализованное состояние.

При расхождении документации с кодом сначала определить, изменилось ли требование или документация устарела. Не исправлять противоречие скрытым предположением.

## Утверждённый стек

- Backend: Python 3.13, Django 6.1.1, Django REST Framework, PostgreSQL.
- Frontend: Node.js 24 LTS, Nuxt 4, Vue 3, TypeScript, Tailwind CSS, Pinia, Nuxt UI.
- Контракт: REST и OpenAPI, генерируемый Django через `drf-spectacular`.
- Фоновые задачи: Celery + Redis. Закрытые файлы: S3-совместимое хранилище.
- Тесты: pytest/pytest-django для backend, Vitest и Playwright для frontend.

Не заменять стек без явного решения пользователя. Наличие технологии в этом списке не означает, что зависимость уже установлена.

## Общие правила разработки

- Права, scope, переходы статусов, начисления, публикация и доступ к файлам проверяются сервером.
- Не заменять отдельного ребёнка взрослым `Account`; не сводить назначения сотрудников к одному полю роли.
- Таблицы хранения не являются DTO. Не отдавать пароли, хеши, закрытые данные и служебные поля.
- Не придумывать продуктовые правила. Блокирующую неопределённость отметить по ID, независимую работу продолжить.
- При изменении бизнес-правила синхронизировать `DOMAIN.md`, затронутые контексты и проверки; при изменении API — OpenAPI, клиент и тесты; при изменении схемы — миграции и `schema.json`.
- Сохранять чужие изменения и менять только область задачи.
- Перед завершением назвать результат, реально выполненные проверки и оставшиеся ограничения.

## Git-коммиты

- Агенты не создают прямые коммиты в `main`; изменения готовятся в короткоживущей feature-ветке для последующего pull request. Человек может коммитить в `main` вручную.
- Сообщение каждого коммита соответствует формату Conventional Commits: `type(scope): subject`.
- `scope` обязателен и отражает затронутую область, например `backend`, `frontend`, `docs`, `infra` или имя модуля.
- `type` выбирать по смыслу: `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `chore`, `perf` или `style`.
- `subject` и, при необходимости, body писать на английском в повелительном наклонении, без точки в конце; breaking change отмечать через `!` после scope и/или footer `BREAKING CHANGE:`.
- Подпись коммита GPG/SSH не обязательна. Не объединять в одном коммите несвязанные изменения.

## Работа в двух IDE

- Каждая IDE начинает с локального `AGENTS.md`; локальный `docs/ai/CONTEXT.md` содержит необходимый минимум без внешних файлов.
- Django владеет OpenAPI-контрактом. Frontend генерирует типы из схемы и не редактирует generated-файл вручную.
- Backend-чат при изменении API передаёт: метод и путь, auth/permissions, request/response DTO, коды ошибок, правила повторов и путь к схеме.
- Решение, затрагивающее обе стороны, фиксируется в `docs/ai/API.md` или `docs/ai/OPEN_QUESTIONS.md`, чтобы чаты не приняли разные правила.
